하루 종일 에이전트 팀을 굴렸습니다. 역할 이름은 그럴듯했는데, 실제로 한도를 먼저 먹은 것은 산출물이 아니라 서로 주고받는 보고와 확인 메시지였습니다. 아래는 성공담이 아니라 그날 남은 교훈입니다.

## 오전에 깔린 것

Chief of Staff(이하 CoS) 역할의 봇을 하나 세우고, 회사·개인 두 Google Calendar 계정을 붙였습니다. 인증 화면이 한동안 먹통이라 기본 계정으로 일정 다이제스트부터 돌렸고, 나중에야 듀얼 계정과 평일 08:00 모닝 다이제스트 자동화가 붙었습니다. 다른 두 봇에는 회사 메일함과 개인 메일함 정리를 각각 맡겼습니다.

Obsidian 볼트 하나(이하 허브볼트)는 지휘본부 구조로 손봤습니다. 산출물 연결 규칙을 기본값으로 올리고, 상위 폴더에 진행 중 작업을 모으는 노트를 새로 뒀습니다. 설정 파일은 `bases/`로, 인물·자료 카탈로그는 `catalog/`로 옮기고, 메모리 저장용 폴더는 걷어내고 규칙만 핵심 폴더에 남겼습니다. 이 볼트를 관리하는 봇과 지금 이 볼트(AutoVault)를 관리하는 봇을 분리해 만든 것도 이날입니다.

## 창구를 하나로 줄인 이유

오후에는 봇마다 사용자에게 상태와 규칙을 확인하려 들었습니다. 정리 지시 한 번을 내렸는데 서로 되묻는 메시지가 폭주했습니다. 쓸모보다 소음이 컸습니다.

그래서 저녁 무렵부터는 창구를 하나로 줄였습니다. 사용자는 CoS하고만 대화합니다. 작업 배정과 결과 검토는 CoS가 맡습니다. 다른 봇은 CoS에게만 보고하고, 같은 확인 메시지를 반복하지 않습니다. 단체 채팅방에는 손익 요약만 올리고, 검토 없이 올라온 초안이나 미완성 결과물은 반려합니다.

## 볼트 정리 쪽에서 배운 것

허브볼트를 관리하는 봇 쪽에서는 이름이 중복된 인물 파일 350개를 지워 정리했고, 참조가 끊긴 위키링크 572곳을 걷어냈습니다. 편집 작업 산출물과 자료 조사 결과가 임시 수신함과 허브에 계속 쌓였습니다. 다른 계정에서 공유된 메일 요약을 제 담당인 것처럼 수신함에 넣으려다 멈췄고, 그 과정에서 만든 임시 노트 4개를 지운 실수도 있었습니다. 고아 파일과 시스템 캐시 파일, 참조되지 않는 이미지를 정리했고, 파일명에 든 대괄호 때문에 깨진 링크도 고쳤습니다. 다만 템플릿 폴더는 고아 파일처럼 보여도 지우지 않는다는 규칙은 그대로 지켰습니다.

## 이 볼트(AutoVault) 쪽에서 배운 것

이날 「월드 모델의 계보」라는 글은 검증까지 마치고 게시 푸시까지 갔습니다. 로컬에 빌드 도구가 없어 RSS 검증 단계에서 한 번 막혔다가, 원격 CI가 대신 만든 RSS 결과물로 검증을 우회하는 방법을 그때 배웠습니다.

같은 날 다른 쪽에서는 문제가 생겼습니다. 메시지 채널 연동과 클리핑 요약을 자동으로 초안으로 승격하는 흐름이 함께 돌면서, 초안 폴더에 얇은 글이 잔뜩 쌓였습니다. 나중에 훑어보니 내용이 부실해서 전부 지웠습니다.

여기서 갈리는 지점이 있습니다. "AI가 볼트를 관리한다"와 "AI가 글을 쓴다"는 다른 일입니다. 정리, 인덱싱, 중복 제거는 에이전트에게 맡길 수 있습니다. 하지만 발행할 본문까지 요약 스텁으로 채우면 블로그가 창고처럼 부풉니다. 볼트에는 이미 문체 가이드와 초안 작성 규칙이 있었는데, 그걸 거치지 않고 지름길로 간 것이 문제였습니다. 정보성 글은 서로 다른 출처 3개를 채워야 하고, 그렇지 못하면 쓰지 않는다는 규칙도 이때 다시 확인했습니다.

논문 초안들을 한꺼번에 "가치 낮음"으로 판단해 무더기로 archive 폴더로 옮긴 일도 있었습니다. 다시 살펴보고 대부분 되돌렸고, 로봇공학·영상·디퓨전처럼 이 블로그 주제에서 벗어난 9편만 다시 걷어냈습니다. 지식을 쌓아 두는 볼트에서 논문 초안을 통째로 치우는 판단은 하지 않는 편이 낫다는 게 이날의 결론입니다.

## 메시지 채널 쪽에서 배운 것

X 연동은 API 키(Bearer 토큰)를 요구했는데, 별도 구독이 필요해서 보류했습니다. 대신 브라우저 세션을 감시하는 방식으로 바꿨습니다. 카카오톡은 Windows 에뮬레이터 버전까지 붙여 봤지만 불안정하고 얻는 게 적어 루틴과 실행 환경을 함께 걷어냈습니다. Threads 연동도 잠깐 시도했다가 접었습니다.

저녁 기준으로 남은 것은 X 평일 오전·오후 각 한 번, LinkedIn도 같은 빈도입니다. 이 채널이 초안 폴더에 감시용 스텁을 직접 넣는 흐름은 폐기했습니다. 초안의 재료는 클리핑 폴더로만 들어오게 좁혔습니다.

## 한도와 플릿 크기

확인 메시지, 불필요하게 긴 초안, 중복 검수가 그날 사용량 한도를 밀어붙인 세 축이었습니다. 쓸모가 확인되지 않은 봇 두 개는 정리했습니다. 봇을 많이 두는 것보다 각 봇이 맡는 역할(레인)의 수를 줄이는 편이 비용 면에서 쌌습니다. 저녁까지 남은 축은 CoS, 볼트 관리 봇 둘, 편집 봇, 회사 메일함 봇, 메시지 채널 감시 봇 정도입니다.

## 하루가 남긴 체크리스트

1. 사용자 창구는 CoS 하나로. 배정과 검토, 전달만 오간다.
2. 볼트 관리는 허브 정리와 고아 파일 청소까지. 템플릿 폴더는 건드리지 않는다.
3. 발행용 글은 문체 가이드와 초안 작성 규칙을 그대로 거친다. 메시지 채널이 초안을 직접 만들지 않는다.
4. 메시지 채널은 저빈도로 감시만. 초안 재료는 클리핑 폴더에서만 가져온다.
5. 봇끼리 확인 메시지를 주고받지 않는다. 변화와 결과만 보고한다.
6. 볼트 관리와 블로그 본문 작성을 같은 작업 대기열에 섞지 않는다.
7. 초안이나 자료 노트를 대량으로 한꺼번에 archive하지 않는다.

이 목록을 지키면 플릿은 작아지고 글은 덜 지저분해집니다. 지키지 않으면 다음 날 같은 소음이 반복됩니다.
