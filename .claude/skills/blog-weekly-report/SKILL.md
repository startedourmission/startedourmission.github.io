# Blog Weekly Report

최근 7일 startedourmission 블로그에 **실제 게시된 글**을 5개 테마로 묶어 요약한 **주간 리포트 노트**를 만든다. 결과물은 볼트 `주간리포트/` 폴더의 노트 한 편.

운영 그림은 이렇다. 블로그가 지금 논문에 쏠려 있어서, 사용자는 한 주 동안 `blog-topic-finder`가 뽑은 다양한 테마의 글을 채워 나간다. 이 스킬은 **매일 돌리며** 그때그때 지난 7일치 게시글을 테마별로 정리해, 한 주가 채워지는 모습을 한눈에 보여준다. 그래서 입력은 우리 블로그 게시글이고, 기간은 실행일 기준 롤링 7일이며, 묶는 축은 요일이 아니라 **테마**다.

헷갈리지 말 것. 외부에서 새 주제를 긁어오는 건 `blog-topic-finder`, 끊어진 링크·방치 초안 점검은 `blog-check`의 일이다.

## 5개 테마 (리포트 섹션)

리포트는 아래 5개 테마를 그대로 섹션으로 쓴다. 지난 7일 게시글을 각 테마 버킷에 담는다.

| 테마 | 무엇이 들어가나 | 블로그 분류로 판별 |
|------|----------------|--------------------|
| 논문 | arXiv 논문 리뷰 | 분류 태그 `논문` 또는 `grid_Papers` 폴더 |
| 모델 릴리스 | 새 모델·제품 출시 소개 | 분류 `정보` 중 모델/제품 출시 내용 |
| 툴·오픈소스 | 개발자 툴·라이브러리·프레임워크·깃허브 | 분류 `정보` 중 툴/OSS 내용 |
| 산업·비즈니스 | 펀딩·인수·기업 전략·정책 | 분류 `정보` 중 산업/비즈니스 내용 |
| 잡담·에세이 | 오피니언·에세이·기술 논쟁 | 분류 태그 `잡담` |

테마는 `blog-topic-finder`가 쓰는 편집 캘린더(월 논문, 화 모델 릴리스, 수 툴, 목 산업, 금 잡담)와 같다. 어느 요일에 올렸는지는 리포트 묶음과 무관하다. 테마는 글 **내용**으로 정한다.

분류가 `정보`인 글은 위 세 테마(모델 릴리스/툴·오픈소스/산업·비즈니스) 중 내용에 맞는 곳으로 보낸다. 셋 중 어디에도 딱 안 맞는 일반 정보글은 가장 가까운 테마에 두고, 정 애매하면 맨 아래 `## 기타`로. `Dictionary`(사전·인물) 항목과 시리즈 강의는 테마에 안 맞으면 `## 기타`에 모은다.

## 워크플로우

### 1. 기간 확정 (기본: 지난 7일 롤링)

```bash
date +%Y-%m-%d      # 오늘 (= 실행일, 파일명·리포트 기준일)
```

기본 기간은 **실행일 기준 지난 7일**(오늘 ~ 오늘-6). 매일 돌리는 전제라 롤링 7일이 맞다. 수집 스크립트에 넘길 `DAYS`는 기본 7.

사용자가 다르게 말하면 맞춘다: "지난 2주" → `DAYS=14`, "어제까지 한 주" 등.

### 2. 게시글 수집

번들 스크립트로 해당 기간 게시글을 찾는다. frontmatter `date` 기준이며 `moc.md`·`index.md` 등 구조용 파일은 자동 제외된다.

```bash
bash "<skill-dir>/scripts/collect_week_posts.sh" 7
```

출력은 `YYYY-MM-DD <TAB> 요일(1-7) <TAB> 상대경로(markdown-blog 기준)` 한 줄씩, 날짜 내림차순. (요일 칼럼은 참고용이고 묶음에는 안 쓴다.)

**0건이면** 빈 노트를 만들지 말고 "지난 7일 게시된 글이 없습니다"라고 사용자에게 알리고 끝낸다.

### 3. 각 글 읽고 테마 분류 + 요약

수집된 각 글을 Read 해서:

- **제목**: 파일명에서 `.md`만 떼면 됨 (`[[제목]]` 위키링크로 Obsidian에서 바로 열림).
- **테마 판별**: 위 「5개 테마」 표 기준. 논문/잡담은 분류 태그로 바로, `정보`는 내용을 보고 모델릴리스/툴/산업 중에 배정.
- **요약**: 본문을 읽고 **2~3문장 한국어 요약**. 무엇을 다룬 글이고 왜 읽을 만한지. 존댓말·블로그 톤.

글이 많으면(10편 이상) 본문 정독 대신 frontmatter `description` + 도입부/소제목 위주로 빠르게 핵심만. 목적은 깊은 리뷰가 아니라 한눈에 훑기다.

### 4. 테마별 섹션 조립

5개 테마를 순서대로 섹션으로 만들고, 각 테마에 해당 글들을 담는다.

- 글이 있으면: `[[제목]]` + 주제 태그 + 2~3문장 요약. (날짜를 한 줄 곁들여도 좋다.)
- 글이 없으면: `(지난 7일 게시 없음)` 한 줄.
- 테마에 안 맞는 글(사전·시리즈 등)은 맨 아래 `## 기타`에. 그것도 없으면 기타 섹션 생략.

맨 위 요약 콜아웃에는 **지난 7일 총 편수 + 테마 분포에서 눈에 띈 점**을 한두 문장으로. (예: "논문 7편으로 쏠렸고 모델릴리스·툴·산업은 아직 공백" 같은 정직한 관찰. 빈 테마가 보이면 한 주를 채우는 데 뭐가 비었는지 사용자가 바로 안다.)

### 5. 노트 저장

`주간리포트/` 폴더에 저장. 폴더가 없으면 Write가 만든다. **매일 돌리므로 파일명은 실행일(오늘) 날짜 기준** 이라 날마다 별도 노트가 쌓인다.

```
주간리포트/<오늘 YYYY-MM-DD> 주간 리포트.md     예: 주간리포트/2026-06-09 주간 리포트.md
```

같은 날짜 파일이 이미 있으면 그날 다시 돌린 것이니 덮어써도 된다(단, 사용자가 직접 손댄 흔적이 보이면 물어본다).

### 6. 사용자 보고

저장 경로, 지난 7일 총 편수, 한 줄 총평을 대화로 보고. 빈 테마가 있으면 짚어준다(그 주 채워야 할 빈자리를 사용자가 인지하도록).

## 출력 템플릿

```markdown
---
date: {오늘 YYYY-MM-DD}
tags:
  - 주간리포트
description: {지난 7일 한 줄 총평}
---

> [!summary] 지난 7일 ({오늘-6 ~ 오늘}) 요약
> 게시 {N}편. {테마 분포·눈에 띈 점 1~2문장}.

## 논문
### [[글 제목]]
- 태그: LLM, 추론
- {2~3문장 요약}

## 모델 릴리스
(지난 7일 게시 없음)

## 툴·오픈소스
(지난 7일 게시 없음)

## 산업·비즈니스
(지난 7일 게시 없음)

## 잡담·에세이
(지난 7일 게시 없음)

## 기타
### [[인물 이름]]
- {1~2문장 요약}
```

## 하면 안 되는 것

- **외부 뉴스·논문을 끌어오기.** 이 스킬은 우리 블로그에 *게시된* 글만 다룬다. 새 주제 발굴은 `blog-topic-finder`.
- **요일로 묶기.** 묶는 축은 테마다. 어느 요일에 올렸는지는 상관없다.
- **본문에 없는 내용 지어내기.** 요약은 실제 글 본문 근거로만.
- **구조용 파일(moc/index/links 등) 포함.** 스크립트가 걸러주지만 수동 수집 시에도 제외.
- **빈 테마에 억지로 글 욱여넣기.** 없는 테마는 `(지난 7일 게시 없음)`으로 정직하게. 빈자리가 보이는 게 이 리포트의 쓸모다.
- **em·en dash(`—` `–`), 이탤릭 사용.** 마침표·쉼표·괄호로 풀어 쓴다 (CLAUDE.md 공통 규칙).
- **본문 H1(`# 제목`) 넣기.** 노트 제목은 파일명이 대신한다.
- **빈 주에 빈 노트 만들기.** 0건이면 노트 없이 사용자에게 보고만.
```
