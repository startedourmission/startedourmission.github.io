# 네이버 블로그 글쓰기

> `raw/drafts/`는 없어졌습니다 (2026-08-31). 초안은 **목적지 폴더에 직접** `ready: false` 로 만듭니다 — 목적지는 `python3 tools/ready_queue.py --dest <태그…>` 가 알려줍니다.

## 1단계: 주제 선정

주제가 주어지지 않았다면 `WebSearch`로 오늘(최대 어제까지)의 AI/기술 뉴스를 검색한다.

- 검색어 예시: `"AI news today June 2026"`, `"AI 기술 뉴스 오늘"`
- 선정 기준: 일반 독자도 "왜 이게 중요하지?" 를 한 문장으로 이해할 수 있는 뉴스
- 너무 기술적이거나 마이너한 소식보다 대형 발표, 정책 변화, 실생활 영향 있는 뉴스 우선

주제가 정해지면 slug를 만든다 (영문 소문자 + 하이픈, 예: `mai-thinking-1-launch`).

## 2단계: 글 작성

아래 구조를 반드시 지킨다.

### 파일명
`naver-{slug}.md`로 `AutoVault/markdown-blog/<목적지>/`에 저장.

### 전체 구조
```
제목
---
[📸 사진 1 - 사진 설명]   ← 사진은 이것 하나만. 나머지는 모두 줄글.

도입부
---
본문 (소제목들)
---
정리
---
태그
```

### 제목
- 핵심 키워드를 앞부분에 배치
- "누가/무엇을/어떻게/왜"가 드러나는 구체적 표현 사용
- 포괄적 표현("AI 근황", "기술 소식") 피하기
- 예: `마이크로소프트 자체 AI 모델 출시 | MAI-Thinking-1 정리`

### 도입부 (3~5줄)
독자가 계속 읽게 만드는 후킹이 목표다.

1. 독자가 뉴스를 보고 가졌을 법한 의문이나 반응을 한 문장으로 던진다
2. 나도 처음엔 그랬다는 공감 한 줄
3. 이 글에서 무엇을 얻을 수 있는지 예고

예:
```
"마이크로소프트가 OpenAI 안 쓰고 AI를 직접 만든다고?"

뉴스 보다가 이 문장에서 멈췄어요. 그냥 지나치려다가 내용 보고 좀 놀랐거든요.

오늘은 MAI-Thinking-1이 뭔지, 왜 이 뉴스가 AI 판에서 의미 있는 건지 정리해볼게요.
```

### 본문
- 소제목은 검색 키워드를 포함한 명사형으로: `## MAI-Thinking-1, 뭐가 다른가요?`
- 핵심 팩트 하나는 인용구 블록(`>`)으로 강조
- 나머지는 모두 줄글. 불릿 리스트 최소화
- 소제목 2~4개가 적당. 너무 잘게 쪼개지 않기
- 단순 사실 나열이 아니라 "왜 이게 중요한지"에 대한 래빗 본인의 시각을 넣는다

### 정리 (결론)
- 핵심 내용을 3줄 이내로 요약
- 다음 글 예고 한 줄 ("다음엔 ~~을 정리해볼게요")
- 댓글 유도 한 줄 ("댓글로 궁금한 점 남겨주세요")

### 태그
5개 이하, 공백으로 구분, 따옴표/# 없이.

## 3단계: 글쓰기 규칙 (AI 말투 제거)

글을 쓴 뒤 아래 항목을 반드시 점검한다.

**문장/리듬**
- 한 문장 20자 내외 유지. 긴 문장은 쪼갠다
- 한 단락 3~4줄
- 종결어미를 다양하게: ~예요, ~거든요, ~죠, ~어요, ~는데요 등 섞기
- 연결어미(~고, ~며, ~지만) 직후 쉼표 금지

**AI 티 제거**
- ~를 통해, ~에 있어서, ~에 대해 → 직접 표현으로
- 결론적으로, 시사하는 바가 크다, 주목할 만하다 → 삭제
- ~할 수 있다 남발 → 단언으로
- ~같아요 반복 → 확신 있는 곳은 ~예요, ~죠로
- 볼드 최소화. 꼭 필요한 곳 1~2개만
- 또한, 따라서, 이에 문두 반복 금지

**톤**
- 이웃집 언니/형이 말해주는 느낌. 딱딱하지 않게
- 래빗 본인이 느낀 점, 의외였던 부분, 솔직한 평가를 짧게라도 넣는다
- 정보만 나열하는 글은 기사지 블로그가 아님

## 체크리스트 (저장 전 확인)

- [ ] 제목에 핵심 키워드 포함
- [ ] 도입부에 후킹 + 예고
- [ ] 사진 플레이스홀더 1개만 (맨 위)
- [ ] 인용구 블록 1개 이상
- [ ] 본문에 래빗 본인 시각 포함
- [ ] 결론에 다음글 예고 + 댓글 유도
- [ ] 태그 5개 이하
- [ ] AI 말투 없음 (쉼표 남발, 볼드 과다, ~같아요 반복 없음)

## 래빗 목소리 정의

이 스킬의 모든 글은 아래 목소리를 따른다. 일반적인 네이버 블로그 "친근한 언니/오빠" 톤이 아니다.

**도입 방식**
- 공감·감성으로 시작하지 않는다
- 팩트나 장면으로 바로 던진다
- 예: "금요일 새벽 2시에 에이전트가 조용히 고장났습니다. 아무도 몰랐습니다."
- 예: "GitHub Copilot 요금제가 6월 1일부로 바뀌었습니다. 청구서 보고 놀란 사람이 꽤 됩니다."

**본문 톤**
- 헷지하지 않는다. "~인 것 같아요" → "~입니다"
- 숫자와 구체적 디테일을 넣는다
- 추상적 설명 전에 예시부터 든다
- 좋은 점만 쓰지 않는다. 한계나 단점도 짧게 언급한다

**마무리**
- 본인 판단이나 입장을 한 줄 박는다
- "저는 ~~합니다/안 합니다" 식으로 명확하게
- "읽어줘서 감사해요", "댓글 남겨주세요" 류 없음
- 다음 글 예고는 필요할 때만. 억지로 넣지 않는다

**문체**
- ~요체 기본 (네이버 독자 고려)
- 단호한 문장은 ~다 / ~습니다로 끝내도 됨
- 문장 짧게. 미사여구 없음

## DIA+ 최적화 (검색 노출 전략)

글을 쓰기 전에 아래를 먼저 생각한다.

### 검색 의도 파악
키워드를 치는 사람이 실제로 원하는 게 뭔지 먼저 정한다.

- **정보형**: "MAI-Thinking-1이 뭔지 알고 싶다" → 개념 설명 + 의미 분석
- **비교형**: "Claude랑 GPT 중 뭐가 나은지" → 차이점 + 상황별 추천
- **후기형**: "실제로 써본 사람 경험 궁금하다" → 본인 경험 + 수치 + 한계

제목과 본문이 같은 의도를 다뤄야 한다. 제목에서 약속한 걸 본문이 지키지 않으면 이탈률이 높아지고 DIA+ 점수가 깎인다.

### 키워드 배치
- 핵심 키워드는 제목 앞부분 + 첫 문단 안에 자연스럽게 넣는다
- 본문 전체에 억지로 반복하지 않는다 (키워드 남용은 오히려 감점)
- 연관 키워드도 자연스럽게 섞는다 (예: "Copilot" 글이면 "GitHub", "코드 자동완성", "AI 요금" 등)

### 수치와 구체성
DIA+는 애매한 표현보다 정확한 수치를 신뢰한다.

- 나쁜 예: "요금이 많이 나왔다는 반응이 있었습니다"
- 좋은 예: "월 구독 대비 3~5배 높은 청구서를 받았다는 사례가 커뮤니티에 올라왔습니다"

수치가 없으면 구체적 상황이라도 넣는다. "개발자 커뮤니티에서"보다 "Hacker News 스레드에서"가 낫다.

### 체류시간 구조
글을 끝까지 읽게 만드는 구조:

1. 도입에서 "이 글을 읽으면 뭘 얻는지" 명확히
2. 소제목으로 흐름을 잡아서 스캔하기 쉽게
3. 본문 중간에 인용구나 핵심 요약 문장으로 호흡 조절
4. 결론에서 핵심을 다시 한 번 짚어주기

### 제목 공식
DIA+는 검색 의도와 제목 일치도를 본다. 제목 작성 시:

- 검색어로 쓸 법한 표현을 앞에 (예: "GitHub Copilot 요금제")
- 구체적 상황이나 결과를 뒤에 (예: "바뀐 이유와 영향")
- 완성형: `GitHub Copilot 요금제 변경 | 토큰 기반 전환 정리`
- 피할 것: `요즘 핫한 AI 소식`, `알아두면 좋은 것들`
