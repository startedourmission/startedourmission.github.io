# Blog to SNS (LinkedIn)

> `raw/drafts/`는 없어졌습니다 (2026-08-31). 초안은 **목적지 폴더에 직접** `ready: false` 로 만듭니다 — 목적지는 `python3 tools/ready_queue.py --dest <태그…>` 가 알려줍니다.

블로그 글 한 편을 사용자의 SNS 말투로 된 LinkedIn 포스트 텍스트로 변환합니다. 게시는 하지 않습니다. 텍스트만 뽑아주면 사용자가 직접 올리고, X용은 사용자가 알아서 잘라 씁니다.

## 범위 — 무엇을 하고 무엇을 안 하는가

- **한다**: 블로그 글/주제를 LinkedIn 포스트 1벌로 변환. 사용자 보이스 적용. 마지막에 블로그 링크 첨부.
- **안 한다**: 자동 게시(Posteady 등 사용 안 함), X 별도 생성(사용자가 LinkedIn 글에서 직접 잘라 씀), 이미지 생성.

기준 플랫폼은 **LinkedIn 하나**입니다. 글자수 제한 없이 장문 구어체로 씁니다.

## 워크플로우

### 1단계 — 대상 글 확보

사용자가 파일명·주제를 지정했으면 그걸 씁니다.

- 게시된 글이면 `markdown-blog/` 하위에서 부분 일치로 찾습니다.
- 초안이면 `ready: false` 인 글에서 찾습니다.
- 방금 작성한 글이 맥락에 있으면 그걸 바로 씁니다.

블로그 본문을 그대로 옮기는 게 아니라, **핵심 주장과 수치를 뽑아 SNS 글로 새로 씁니다.** 본문이 길면 가장 강한 포인트 2~3개만 추립니다.

### 2단계 — LinkedIn 포스트 작성 (보이스 가이드 적용)

아래 "사용자 SNS 보이스"를 반드시 따릅니다. 블로그용 STYLE.md(단정·감상제거)와는 다릅니다. SNS는 더 캐주얼하고 드립이 들어갑니다.

### 3단계 — 블로그 링크 첨부

글 맨 아래에 블로그 URL을 답니다. URL은 파일명(`.md` 제외)의 MD5 앞 8자리입니다.

```python
import hashlib
slug = "파일명에서 .md 제외한 제목"
hash_id = hashlib.md5(slug.encode("utf-8")).hexdigest()[:8]
url = f"https://startedourmission.github.io/{hash_id}.html"
```

게시 전 글이라 아직 URL이 없으면, 링크 자리를 비워두고 "게시 후 링크 추가"라고 표시합니다.

### 4단계 — 출력

완성된 LinkedIn 텍스트를 코드블록이 아닌 일반 텍스트로 보여줍니다(복붙하기 좋게). 게시는 사용자가 직접 한다고 안내합니다. 수정 요청 있으면 반영합니다.

## 사용자 SNS 보이스 (가장 중요)

이 보이스는 사용자가 직접 다듬은 LinkedIn 글에서 역으로 뽑은 규칙입니다. 블로그 문체와 별개입니다.

### 훅 — 첫 줄은 밈·드립으로

번역투 카피("어제는 천재였는데 오늘은 바보가 됐다") 말고, 한국어 밈·말장난·라임으로 잡습니다.

- 좋음: `어제는 우리 클로드, 오늘은 느그 클로드`
- 나쁨: `같은 모델인데 성능이 들쑥날쑥한 이유` (그냥 제목)
- 나쁨: `어제는 천재였는데, 오늘은 바보가 됐다` (번역투 카피)

첫 줄이 LinkedIn 미리보기에서 펼치기 전 보이는 부분이라 제일 중요합니다.

### 구어체 — 혼잣말과 늘임표

독자의 속마음을 따옴표 안 혼잣말로 묘사하고, `~`로 늘여 말맛을 냅니다.

- `그저 '요즘 사용자가 많이 몰리나~' 내지는 '뭐가 조용하게 바뀌었나' 하고 말았죠.`
- `이제는 이유가 궁금하지도 않습니다.`

말줄임 `,,`도 가능. 단 이모지는 안 씁니다(볼트 공통 규칙). em/en dash, 이탤릭도 금지.

### 소제목 — 한글 번호 + 짧게, 질문형 허용

`## 1. 같은 모델이...` 같은 설명형 말고, 한글로 짧게. 후킹되면 질문형도 좋습니다.

- 좋음: `하나, 서버 부하`
- 좋음: `셋, 프롬프트를 줄였는데 오히려 느려졌다?`
- 나쁨: `1. 같은 모델이 같은 질문에 다른 답을 한다`

### 표 금지 — 전부 줄글로

블로그에서는 수치를 표로 정리하지만, SNS에서는 표가 깨집니다. 모든 수치를 문장으로 풀어씁니다.

- 블로그: `| 고유 출력 | 80개 |`
- SNS: `이 설정으로 1000번 돌렸더니, 80개의 서로 다른 답이 나왔습니다.`

### 분량 — 짧게, 핵심 3개

블로그가 H2 5~7개라면 SNS는 포인트 **3개로 압축**합니다. "세 가지만 추려봅니다"처럼 개수를 명시하면 읽는 부담이 줄어듭니다.

### 강조 — 아껴서 한 방

볼드는 글 전체에서 결론 한 문장에만. 여기저기 굵게 하지 않습니다.

- `우리는 **한 번 잘 됐다고 "이 모델 좋다", 한 번 망쳤다고 "이 모델 별로다" 단정하지 말아야 합니다.**`

### 호칭 — 한글 음차, 친근하게

`Claude` 대신 `클로드`, 때로 `우리 클로드`. 영문 고유명사를 한글로 풀어 친근하게. 단 정확성이 중요한 출처·논문명은 원문 유지(예: "Thinking Machines Lab", "arXiv:2506.09501").

### 출처 — 맨 아래 간단히

본문에 출처를 끼우지 않고, 글 맨 끝에 `참조 :` 한 줄로 모읍니다.

```
참조 :
Thinking Machines Lab "Defeating Nondeterminism in LLM Inference"
Anthropic 포스트모템 2025.09, NeurIPS 2025 arXiv:2506.09501
```

## 주의사항

- 게시하지 않습니다. 텍스트만 출력하고 사용자가 직접 올립니다.
- Dictionary 카테고리 글은 SNS 대상에서 제외합니다.
- 수치는 블로그 본문/검증된 출처에서만 가져옵니다. SNS라고 과장하지 않습니다.
- 블로그 본문을 통째로 복사하지 않습니다. 가장 강한 포인트만 SNS 호흡으로 재구성합니다.
