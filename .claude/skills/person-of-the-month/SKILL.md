# Person of the Month

> `raw/drafts/`는 없어졌습니다 (2026-08-31). 초안은 **목적지 폴더에 직접** `ready: false` 로 만듭니다 — 목적지는 `python3 tools/ready_queue.py --dest <태그…>` 가 알려줍니다.

해당 월에 **논문 폼이 두드러졌던 연구자**를 선정하고, 그 활약을 정리한 `잡담` 칼럼 초안을 목적지 폴더에 생성한다. 복수 선정 가능.

이 스킬은 단순 인물 소개가 아니라 **"왜 이달에 이 사람인가?"** 를 독자에게 납득시키는 글을 목표로 한다. 그 달 논문들을 꿰뚫는 공통 테마, 연구 흐름의 변곡점, 업계에서 벌어진 맥락까지 담아야 한다.

---

## 1단계 — 대상 월 확정

사용자가 월을 명시했으면 그대로 쓴다. 명시 없으면 **오늘 날짜의 전월**을 기본으로 하되, 오늘이 해당 월 초순(1~7일)이면 전전월도 후보로 물어본다.

예: 오늘이 2026-06-14이면 → 기본 대상월 **2026년 5월**. 사용자 확인 없이 진행.

**헤드리스 자동 모드.** 호출 프롬프트에 "헤드리스 자동 모드" 또는 arg `auto`가 있으면(새벽 launchd 크론이 그렇게 부름) 사용자에게 묻지 않는다.

1. `markdown-blog/grid_Posts/`와 목적지 폴더를 합쳐 `YYYY. MM. 이달의 인물` 패턴 파일을 전부 찾아 가장 최근 대상월을 구한다.
2. 그다음 달(대상월 + 1개월)이 **오늘 기준으로 이미 끝난 달**이면(오늘이 그다음 달보다 뒤 달이면) 그 달을 이번 실행의 대상월로 정한다.
3. 그다음 달이 아직 진행 중이거나 미래면 할 일 없음으로 보고 종료한다(하루 앞선 실행으로 이미 커버됨, 또는 아직 그 달이 안 끝남).
4. 5단계에서 같은 대상월 파일이 이미 있으면(초안이든 게시본이든) 덮어쓰지 않고 "이미 처리됨"으로 로그만 남기고 종료한다. AskUserQuestion을 호출하지 않는다.
5. 이 모드에서도 3단계(자동 선정), 4단계(조사), 6단계(보고)는 그대로 수행한다. 6단계 보고는 stdout으로만 낸다.

## 2단계 — 후보 발굴

두 채널을 동시에 훑는다.

### A. 우리 블로그 논문 리뷰 스캔

`markdown-blog/grid_Papers/` 에서 해당 월(`date: YYYY-MM-*`)에 해당하는 논문 파일을 수집한다.

```bash
grep -rl "date: YYYY-MM" "markdown-blog/grid_Papers/" 2>/dev/null
```

각 파일의 프론트매터 `date`와 본문에서 **주저자·교신저자 이름**을 읽어낸다. 논문 정보 블록(`> **저자:**`) 또는 본문에서 추출. 이름이 반복될수록 가중치를 둔다.

### B. WebSearch — 월별 AI 연구 화제 인물

다음 쿼리 패턴으로 검색한다:

```
"[YEAR] [MONTH] AI research notable papers [researcher name]"
"arXiv [YEAR-MM] trending AI papers author"
"[MONTH] [YEAR] machine learning breakthrough researcher"
```

HuggingFace Papers, arXiv monthly trending, Papers with Code 등에서 해당 월 가장 많이 언급된 저자를 찾는다. 우리 블로그에서 이미 다룬 논문의 저자와 겹치면 가중치를 높인다.

### 후보 선별 기준

아래 중 두 가지 이상 해당하는 인물을 후보로 올린다:

| 기준 | 설명 |
|------|------|
| **다작** | 해당 월에 논문 2편 이상 발표 (공저 포함) |
| **임팩트** | HF Papers 상단, HN 100pts+, X 바이럴 등 buzz 시그널 |
| **전환점** | 기존 연구 노선을 바꾸거나 새 방향성 제시 |
| **업계 반응** | 재현 시도·후속 연구·비판 논문 등 즉각적 반응 |
| **우리 블로그 언급** | 해당 월 우리가 직접 리뷰한 논문의 저자 |

## 3단계 — 자동 선정 및 보고

후보 중 선별 기준이 두 가지 이상 해당하는 인물 1~3명을 자동 선정해 **바로 드래프트 작성으로 진행한다.** 사용자 확인을 기다리지 않는다.

선정 우선순위:
1. 우리 블로그 리뷰 논문의 저자 + 외부 buzz 시그널 동시 충족 (최우선)
2. 외부 buzz 시그널이 가장 강한 순서 (NeurIPS 어워드 > GitHub Trending > HF upvotes)
3. 3명 이상이면 상위 3명만 선정. 동점이면 우리 블로그 연결 있는 쪽 우선

선정 결과는 드래프트 저장 후 사용자에게 한 줄로 보고한다. ("Dan Hendrycks, Yejin Choi, Chao Huang 세 명으로 선정해 드래프트를 생성했습니다.")

사용자가 스킬 실행 전에 특정 인물을 명시했거나, 실행 후 교체를 요청하면 해당 인물로 드래프트를 다시 쓴다.

## 4단계 — 인물별 심층 조사

선정된 각 인물에 대해 다음을 조사한다.

### 조사 항목

1. **해당 월 논문 목록** — 제목, 공저자, arXiv 링크, 핵심 기여 1~2문장
2. **기존 연구 흐름 대비 이번 달 의미** — "이 사람이 원래 무엇을 해왔고, 이번 달 어디로 향했나"
3. **업계 반응** — 인용, 재현, 비판, 후속 연구
4. **개인 발언** — X, 블로그, 인터뷰에서 해당 월에 한 말 (있으면)
5. **Dictionary 항목 존재 여부** — `markdown-blog/Dictionary/[이름].md` 파일 존재 확인

조사 도구:
- `WebSearch` — 논문 발표 뉴스, X 스레드, 블로그 포스트
- `WebFetch` — arXiv abstract, HF Papers 페이지, 저자 홈페이지
- `mcp__zotero__zotero_search_items` — Zotero에 해당 논문이 있으면 전문 활용

### Dictionary 항목 처리

**파일이 있는 경우**: 해당 파일을 Read해 내용을 파악하고, 이달 활약을 반영해 내용을 보강할지 여부를 사용자에게 알린다. 직접 수정하지는 않는다 — 이 스킬의 산출물은 목적지 폴더 초안 하나뿐이다.

**파일이 없는 경우**: 선정된 인물의 Dictionary 항목을 **초안 작성 전에 먼저 생성한다.** 항목 없이 초안을 쓰면 위키링크가 끊어진다. 항목 생성 형식은 아래 "Dictionary 항목 생성 형식" 참고.

#### Dictionary 항목 생성 형식 (인물 신규 진입 시)

`markdown-blog/Dictionary/<이름>.md` 에 생성. 필수 필드:

```yaml
---
type: person
description: <소속, 대표 연구, 역할 한 줄>
tags:
  - <LLM | 머신러닝 | 딥러닝 | AI평가 | 오픈소스 | NLP | ...>
aliases:
  - <영문 이름>
  - <한국어 이름 (있으면)>
---
```

본문은 3~5문단. 현재 소속, 대표 연구 1~2건(연도/발표처/핵심 기여), 이달 활약에서의 위치.

## 4.5단계 — 위키링크 목록 작성 (초안 쓰기 전 필수)

초안 본문을 쓰기 전에 반드시 다음을 수행한다.

```bash
ls "markdown-blog/Dictionary/"
```

위 목록과 본문에 등장할 **모든 인물, 모델, 벤치마크, 개념, 기관**을 대조해 링크 가능 항목을 미리 파악한다. 초안을 쓰는 동안 첫 등장마다 `[[항목명]]`을 달고, 파일명과 표시 텍스트가 다를 때는 `[[파일명|표시 텍스트]]`를 쓴다.

**링크 체크 대상 (빠지기 쉬운 것)**

| 항목 유형 | 예시 |
|----------|------|
| 선정 인물 | H2·H3 제목 + 본문 첫 등장 모두 `[[이름]]` |
| 공저자·협력자 | 이름 최초 등장 시 Dictionary 확인 후 링크 |
| 벤치마크 | MMLU, ARC, HLE, GSM8K, HellaSwag 등 |
| 개념·기법 | RAG, RLHF, 확산모델 등 Dictionary 항목 있으면 연결 |
| AI 모델 | GPT-4, Claude, Qwen 등 Dictionary 항목 확인 |
| 기관·랩 | Dictionary 항목 없으면 괄호 설명으로 대체 (링크 금지) |

**금지**: Dictionary 항목이 없는 이름에 `[[링크]]` 달기. 깨진 링크는 빌드 오류의 원인이 된다. 항목이 없으면 링크 없이 평문으로 쓰거나, 중요하면 항목을 먼저 만든다.

## 5단계 — 초안 작성

### 파일명 및 저장 위치

```
markdown-blog/<목적지>/YYYY. MM. 이달의 인물 - <이름1>, <이름2>, ....md
```

예: `markdown-blog/<목적지>/2026. 05. 이달의 인물 - Yann LeCun, Sasha Rush.md`

- 연-월 형식은 `YYYY. MM.` (점 구분, 월은 두 자리)
- 선정 인물이 1명이면 `- <이름>`, 복수면 `, `로 이어 붙인다
- 이름은 풀네임 그대로. 파일명에 `:`, `?`, `/` 는 쓰지 않는다

같은 이름 파일이 이미 있으면 사용자에게 알리고 덮어쓸지 새 이름으로 할지 물어본다.

### 프론트매터

```yaml
---
date: <오늘 날짜 YYYY-MM-DD>
tags:
  - 잡담
description: "<YYYY년 MM월> 논문 폼이 돋보였던 연구자를 돌아봅니다."
---
```

- `Headliner` 태그는 절대 붙이지 않는다.
- 인물이 여럿이면 description에 "YYYY년 MM월, 이달을 빛낸 연구자들을 돌아봅니다." 같은 복수형으로.

### 본문 구조

선정 인물이 1명일 때와 복수일 때 구조를 달리한다.

#### 단독 선정 (1명)

```
(도입 — 날짜 명시 없이 바로 핵심 관찰로 시작. 이 달 이 사람이 왜 두드러졌는지 2~3문장.)

## [[인물명]]

[[인물명]]은 ... (소속·배경 1~2문장, 이달 논문 언급)

### [[논문 제목]]
(핵심 기여, 메커니즘, 왜 중요한지. 2~4문단.)

### 선정 이유
(이 달 연구 흐름에서 어떤 의미인지. 기존 궤적 대비 이번 달의 위치.)
```

#### 복수 선정 (2명 이상)

```
(도입 — 날짜 명시 없이 바로 이달 AI 연구 분위기로 시작. 선정 인물들을 관통하는 흐름이 있으면 암시.)

## [[이름 1]]

[[이름 1]]은 ... (소속·배경 1~2문장)

### [[논문 제목]]
(핵심 기여 + 맥락. 2~4문단.)

### 선정 이유
(이 달 연구 흐름에서 어떤 의미인지.)

---

## [[이름 2]]
(동일 구조.)

---

(마지막 인물 섹션 뒤 구분선 없이)

(마무리 단락 — 여러 명의 활약을 관통하는 공통 테마가 있으면 자연스럽게 한 단락으로 녹여 쓴다. "## 공통 테마" 같은 별도 섹션을 만들지 않는다. 공통점이 없으면 생략.)
```

**구조 규칙:**
- 논문 H3 제목은 반드시 `### [[논문 제목]]` 형식으로. 위키링크가 blog post와 연결된다
- "왜 이달에 X인가" 같은 설명적 제목 대신 `### 선정 이유`로 통일
- 인물 간 구분은 `---` 구분선 사용. 단, 마지막 인물 뒤에는 구분선 없이 마무리 단락으로
- 공통 테마는 별도 섹션(##)이 아니라 마지막 단락으로 자연스럽게 통합

### 라이팅 원칙

- 존댓말 기반, 친근하되 전문적인 톤. "~했습니다", "~네요", "~죠"
- 이모지 절대 금지
- 과장 표현 금지: "놀라운", "혁신적인", "세계 최초" 등
- 수치는 논문·공식 발표 기반으로만. 출처 불명 수치 금지
- `[[인물명]]`, `[[논문명]]` 위키링크 적극 활용. Dictionary에 있는 모든 인물·개념은 첫 등장 시 연결
- H1 본문 금지 (빌드가 파일명으로 자동 생성)
- em dash(`—`), en dash(`–`) 금지. 마침표·쉼표·괄호로 풀어 쓴다
- 이탤릭 금지

### 깊이 기준

단순 업적 나열이 아니라 **"왜 이 달에 이 사람인가"** 를 설득해야 한다.

- 이번 달 논문이 기존 연구 흐름에서 어떤 의미인지 설명
- 논문의 메커니즘을 한 단락이라도 설명 (추상 요약 금지)
- 업계 반응이 왜 그랬는지 맥락 설명
- 읽는 독자가 "아, 이 사람 이번 달 진짜 잘 했구나" 납득할 수 있어야 함

## 6단계 — 산출물 보고

초안 파일 저장 후 사용자에게:

1. 저장 경로
2. 선정 인물 목록
3. Dictionary 항목 미존재 인물 목록 (있으면)
4. "게시하려면 `blog-publish` 스킬을 쓰세요" 안내

## 하면 안 되는 것

- **Headliner 태그 임의 부여** — 절대 금지. 사용자 전용.
- **본문에 H1 넣기** — 빌드가 파일명으로 제목을 자동 생성한다.
- **이모지·em dash·이탤릭 사용** — CLAUDE.md 공통 금지 사항.
- **검증되지 않은 수치 서술** — "X% 향상" 등 출처 없는 수치 금지.
- **Dictionary 항목 없는 인물을 링크 없이 서술** — 파일이 없으면 링크 없이 쓰되, 사용자에게 항목 생성 여부를 물어본다.
- **`ready: false` 없이 생성** — 이 스킬의 유일한 산출물은 drafts 초안이다. Dictionary 수정은 사용자 동의 후 별도 작업.
- **블로그에 없는 달의 인물을 선정** — 조사는 WebSearch 기반이지만, 우리 블로그 리뷰와 연결 고리가 없으면 선정 우선순위에서 밀린다.
- **한 달에 너무 많은 인물 선정** — 기본 1~3명. 5명 이상은 글이 산만해진다. 사용자가 명시적으로 요청한 경우만 5명 이상 허용.
