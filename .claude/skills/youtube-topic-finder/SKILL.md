# YouTube Topic Finder

블로그 게시글 없이 웹 서치로 유튜브 에피소드 주제를 독자적으로 발굴하고, Linear `Podcast 2026`에 Document + Issue로 저장합니다.

이 채널의 정체성: **완전 비개발자 대상 30분 longform 팟캐스트**. 진행자 + 진우 2인 대화체. 돈·일상·사회와 닿는 **시사·사회·경제·국제 이슈**가 핵심. 기술 이슈는 사회적 영향이 클 때만 — 기술 자체가 아닌 "그래서 우리 삶이 어떻게 바뀌나" 관점에서만 다룸. 순수 기술 주제는 다른 스킬이 커버하므로 이 스킬에서 제외.

## Linear 타겟 (고정값)

| 항목 | 값 |
|------|-----|
| 팀 | `cjw&hws` |
| 프로젝트 | `Podcast 2026` |

**생성 순서: Document 먼저 → URL 받은 후 Issue 생성.** 반드시 둘 다 만들 것.

### Document (`mcp__linear__save_document`)
- `title`: 에피소드 제목
- `project`: `Podcast 2026`
- `content`: **스크립트 전문만** (발굴 근거·구성·체크리스트 등 나머지는 이슈에)

### Issue (`mcp__linear__save_issue`)
- `title`: 에피소드 제목 그대로 — 접두어(`EP`, `[업로드]` 등) 일절 붙이지 않음
- `team`: `cjw&hws`
- `project`: `Podcast 2026`
- `state`: `Backlog`
- `priority`: 높음→`2`, 보통→`3`, 낮음→`4`
- `labels`: `["upload"]`
- `description`: 발굴 근거 + 구성 + B-roll + 체크리스트 + 회고 + 스크립트 링크

두 툴 모두 deferred — `ToolSearch`로 먼저 로드.

## 워크플로우

### 0단계 — 기존 이슈 목록 확인 (중복 방지)

**웹 서치 전에 반드시 먼저 실행.**

`mcp__linear__list_issues` (deferred → `ToolSearch`로 먼저 로드)
- `project`: `Podcast 2026`
- `includeArchived`: `true`
- `limit`: `250`

반환된 이슈 제목 전체를 메모리에 보관. 이후 2·3단계에서 발굴한 후보가 기존 이슈 주제와 **동일하거나 실질적으로 같은 각도**면 즉시 제외 — 각도·앵글만 다른 경우도 제외.

### 1단계 — 도메인별 웹 서치

`WebSearch` 툴 사용 (deferred → `ToolSearch`로 먼저 로드). 아래 5개 도메인을 병렬로 검색.

| 도메인 | 검색 쿼리 예시 (한국어·영어 병행) |
|--------|----------------------------------|
| 한국 사회·경제 논란 | `"한국 사회 논란 2026"`, `"물가 부동산 논란"`, `"한국 세대갈등 이슈"`, `"직장 노동 이슈 2026"` |
| 국제 시사·지정학 | `"국제 뉴스 2026"`, `"geopolitics 2026"`, `"미국 정치 경제 논란"`, `"global news controversy June 2026"` |
| 경제·금융·기업 | `"한국 경제 논란 2026"`, `"기업 스캔들 2026"`, `"금융 이슈 2026"`, `"consumer prices controversy 2026"` |
| 사회·문화·젠더·세대 | `"한국 사회 문화 논란"`, `"결혼 출산 트렌드 2026"`, `"MZ세대 직장 이슈"`, `"social controversy Korea 2026"` |
| 기술의 사회적 충격 | `"AI 일자리 사회 영향 2026"`, `"딥페이크 범죄 사회"`, `"기술 변화 사회 충격"` — **기술 자체가 아닌 사회·생활 영향에 한정** |

각 도메인당 최소 3개 쿼리 실행. 헤드라인·URL·날짜 수집.

### 2단계 — 채널 적합성 필터

수집한 후보를 아래 기준으로 걸러 **상위 5~8개**를 선정:

**통과 기준 (모두 충족해야 함):**
- 비개발자도 한 번 듣고 이해 가능한가? (일자리·돈·일상과 연결되는가)
- 서사가 있는가? (사건/논란/극적 반전/놀라운 수치/인물 대립)
- 최근 7~30일 내 주요 매체 보도 또는 evergreen 강한 가치가 있는가?
- 시각화 여지가 있는가? (차트·인물·뉴스 클립·화면 시연)

**제외 기준:**
- 기술 세부사항 자체가 주제인 것 (GitHub 요금제, 모델 벤치마크, 개발 툴 논란 등) — 사회적 파급이 없으면 제외
- 기술 이슈라도 "그래서 내 일자리/생활/돈에 어떤 영향?" 없이 기술 자체만 다루면 제외
- 이미 한국어 유튜브 채널이 충분히 다룬 주제
- 한 달+ 지난 이슈 (evergreen 가치 없는 경우)

### 3단계 — 후보별 심층 분석

각 후보에 대해 추가 검색으로 다음을 확정:

**3-1. 우선순위 (높음 / 보통 / 낮음)**
- 높음: 최근 7일 내 다수 주요 매체 보도 + 일자리·돈·일상 직결 + 한국어 커버 부족
- 보통: 1~3주 내 일부 보도 또는 evergreen 강한 가치
- 낮음: 한 달+ 지남 / 특수 도메인 / 검색 빈약

**3-2. 타겟 시청자**
- 완전 비개발자 (기본값 — 일반 매체 헤드라인 존재 시)
- 얕은 관심층 (IT 뉴스 챙기는 일반인, IT 전문지 위주 보도)
- 개발자도 웃김 (강한 근거 필요, 마지막 선택)

**3-3. 제목 후보 3개 (angle별)**
- 호기심형: `"왜 X는 안 죽을까"`, `"X의 진짜 이유"`
- 단정·도발형: `"X는 사실 Y다"`, `"X가 졌다"`
- 사건·뉴스형: `"X에 무슨 일이 일어났나"`, `"X가 폭로됐다"`

**3-4. 썸네일 문구 후보 3개** (2~4단어, 단정/도발)

**3-5. 후킹 포인트** (첫 15초 한 문장 — 익숙한 패턴 + 모순 구조)

**3-6. 스크립트 골격** — 도입·본론①②③·마무리 핵심 포인트

### 4단계 — Linear Document + Issue 생성

**확인 없이 바로 생성. Document 먼저, Issue 나중.**

**Document 생성은 Haiku 서브에이전트에 위임.** Agent 툴 (`model: "haiku"`) 호출 시 제목·프로젝트 ID·content 전체를 프롬프트에 포함하고, ToolSearch로 `mcp__claude_ai_Linear__save_document` 먼저 로드하도록 지시. 에피소드가 여러 개면 병렬 실행. Issue 생성은 메인 에이전트가 Document URL 받은 뒤 직접 처리.

#### Document content 구조 (스크립트만, 이모지 없음):

```markdown
## 스크립트 전문

청중: 완전 비개발자. 분량: 25~30분 longform.

**진행자** = 질문·반응·정리만 담당. 설명하지 않음. 1~2문장으로 끼어들기.
**진우** = 정보 설명 담당. 핵심 사실·수치·인물·메커니즘을 풀어 설명.
절대 역할 바꾸지 않음 — 진행자가 설명하거나 진우가 질문하면 안 됨.

### 도입 (2~3분)

**진행자:** {훅 제시 + 오늘 주제 한 줄}

**진우:** {충격 한 방 — 핵심 수치나 사건}

**진행자:** {반응 + 청취자 흥미 유도}

…

### 본론 1 — {부제} (7~10분)

**진행자:** {질문}

**진우:** {설명, 구체적 인물·날짜·수치}

**진행자:** {츳코미 또는 추가 질문}

**진우:** {심화 설명}

…

### 본론 2 — {부제} (7~10분)

…

### 본론 3 — {부제} (5~8분)

…

### 마무리 + CTA (2~3분)

…
```

## 스크립트 작성 규칙

**이 채널은 30분 내외 longform 팟캐스트.** 분량 기준: 25~30분 = 5,000~6,000 단어 (한국어 200wpm).

**2인 대화체:**
- `**진행자:**` — 질문·츳코미·정리. 1~2문장 안에 끼어들어야 톤이 살아남.
- `**진우:**` — 설명 담당. 핵심 정보·수치·인물 풀이.
- 화자 사이 빈 줄 한 칸씩. 한 사람이 길게 독주하지 않도록.

**톤:** 존댓말, 잡담·예능 톤. 딱딱한 발표체 X.

**비개발자 원칙:**
- 개발 전문 용어 그대로 쓰지 않음. 어쩔 수 없으면 즉시 풀이.
- 고유명사 첫 등장 때 진행자가 "그게 뭐예요?"로 받아 풀이 유도.
- 숫자는 단위·규모감과 함께.
- 개발자 내부자 농담 금지.

## 카피 가이드

**제목:** 의문문 또는 단정형, 20자 내외.
**후킹:** 익숙한 패턴 + 그 안의 모순. 감정 있는 한 문장.
**썸네일:** 2~4단어, 단정·도발. 한국어 우선.

## 하면 안 되는 것

- 데이터 분석 건너뛰기.
- Document 없이 Issue만 만들기 (반드시 둘 다).
- Issue 없이 Document만 만들기 (반드시 둘 다).
- Document 먼저 만들고 URL 받은 뒤 Issue 만드는 순서 어기기.
- 중간 확인 받기 — 분석·생성을 한 흐름으로, 결과만 보고.
- 본문에 이모지 사용.
- 썸네일 5단어 이상.
- 클릭베이트 과장 표현 (`충격`, `소름`, `미쳤다`).
- 영문 그대로 썸네일에 넣기.
- 스크립트 분량 줄이기 — 30분 longform.
