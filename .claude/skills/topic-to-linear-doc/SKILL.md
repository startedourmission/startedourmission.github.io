# Topic → Linear Document

**문서 생성은 반드시 Haiku 서브에이전트에게 위임.**

## 워크플로우

### 1단계 — 최신 업데이트 읽기

`mcp__claude_ai_Linear__get_status_updates` (deferred → ToolSearch로 먼저 로드)
- `type`: `project`
- `project`: `5a0e726e-13a3-4167-851c-54055054a6b3`

가장 최신 업데이트의 `body`에서 주제 목록 파싱.

### 2단계 — EP 번호 확정

`mcp__claude_ai_Linear__list_documents` (deferred → ToolSearch로 먼저 로드)로 Podcast 2026 기존 문서 목록 확인 → 현재 최대 EP 번호 파악 → 이어서 번호 부여.

### 3단계 — Haiku 서브에이전트로 리서치 + 문서 생성

주제별로 Agent 툴 (`model: "haiku"`) 호출. 주제가 여러 개면 병렬 실행.

Haiku 서브에이전트가 할 일:
1. `WebSearch` (deferred → ToolSearch 로드)로 주제 관련 최신 뉴스·사건·수치 검색 (최소 3개 쿼리)
2. 검색 결과 기반으로 아래 섹션을 **실제 내용으로** 채워서 `save_document` 호출

서브에이전트 프롬프트에 반드시 포함:
- 주제 (status update에서 파싱한 텍스트)
- 문서 제목: `EP{번호}` (주제명 포함 금지)
- Linear 프로젝트 ID: `5a0e726e-13a3-4167-851c-54055054a6b3`
- 채널 정체성: 완전 비개발자 대상 30분 longform 팟캐스트, 진행자+진우 2인 대화체
- 아래 Content 구조 + 작성 지침 전체
- MCP 툴 로드 지시: ToolSearch로 `WebSearch`, `mcp__claude_ai_Linear__save_document` 먼저 로드

### 4단계 — 프로젝트 Description 표 업데이트 (훅)

Haiku가 문서 생성 완료 후, **메인 에이전트가** 아래 순서로 처리:

1. `mcp__claude_ai_Linear__get_project` (`query`: `5a0e726e-13a3-4167-851c-54055054a6b3`)로 **현재 description을 반드시 먼저 읽는다.** 캐시·기억·이전 스냅샷 절대 사용 금지.
2. 읽어온 description 문자열 맨 아래에 새 행만 추가.
3. `mcp__claude_ai_Linear__save_project`로 저장.

새 행 형식:
```
| [EP{번호}](<{document_url}>) | {주제명} | {생성일} | * | 미정 |
```

**이 단계는 생략 불가. 반드시 get_project → 수정 → save_project 순서.**

## Content 구조 및 작성 지침

Haiku 서브에이전트가 채워야 하는 섹션. 플레이스홀더(`요약1`, `제목1` 등) 금지 — 검색 결과 기반으로 실제 내용 작성.

## 오프닝 (2~3분)

### 작성 규칙

- **전체 분량: 30분 내외 = 한국어 약 5,000~6,000단어.** 짧으면 안 됨.
- **스크립트(`# 스크립트` 하위 전체)는 코드블록 사용 금지.** 일반 마크다운으로 작성.
- **스크립트 전체는 반드시 존댓말.** 반말 금지.
- **스크립트는 반드시 `**진행자:**` / `**진우:**` 2인 대화체**로 작성. 설명문·개요 형식 금지.
- 동그라미 숫자(①②③) 사용 금지 — 대신 `1`, `2`, `3` 또는 `본론 1`, `본론 2` 사용.
- 한 사람이 길게 독주하지 않도록. 자연스럽게 주고받을 것.
- 존댓말, 잡담·예능 톤. 딱딱한 발표체 금지.
- 개발 전문 용어 그대로 쓰지 않음. 어쩔 수 없으면 즉시 풀이.
- 고유명사 첫 등장 때 진행자가 "그게 뭐예요?"로 받아 풀이 유도.
- 썸네일 5단어 이상 금지.
- 이모지 금지.

## 하면 안 되는 것

- 제목에 주제명 포함 (`EP014 - 주제명` 형식 금지 → `EP014`만)
- 플레이스홀더 그대로 제출 (`요약1`, `제목1`, `오프닝 멘트 작성` 등)
- 스크립트 본문을 설명문·개요·bullet로 작성 (반드시 대화 형식)
- 동그라미 숫자 사용 (①②③ 금지)
- 오프닝·스크립트 본문·클로징에 코드블록 빠뜨리는 것 금지
- 분량 부족 (30분 미만 = 5,000단어 미만 금지)
- 리서치 없이 내용 작성
- 메인 에이전트가 직접 `save_document` 호출 — 반드시 Haiku에 위임
- EP 번호 확인 없이 임의 부여
- 중간 확인 받기
