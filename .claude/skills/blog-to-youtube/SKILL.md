# YouTube Episode Creator

주제 소스에 상관없이 — 블로그 게시글, 사용자가 직접 준 주제 문자열, 뉴스 링크 등 — 유튜브 에피소드를 Linear `Podcast 2026`에 생성합니다.

## Linear 타겟 정보 (고정값)

| 항목 | 값 |
|------|-----|
| 팀 | `cjw&hws` |
| 프로젝트 | `Podcast 2026` |

**생성 순서: Document 먼저 → Issue 나중.** 문서 URL을 이슈 description에 넣어야 하므로 순서가 중요합니다.

### Document (`mcp__linear__save_document`)

| 필드 | 값 |
|------|-----|
| `title` | 에피소드 제목 (영상용 카피) |
| `project` | `Podcast 2026` |
| `content` | 아래 본문 구조 전체 |

### Issue (`mcp__linear__save_issue`)

| 필드 | 값 |
|------|-----|
| `title` | 에피소드 제목 그대로 — 접두어(`EP`, `[업로드]` 등) 일절 붙이지 않음 |
| `team` | `cjw&hws` |
| `project` | `Podcast 2026` |
| `state` | `Backlog` |
| `priority` | 높음 → `2`, 보통 → `3`, 낮음 → `4` |
| `labels` | `["upload"]` |
| `description` | 발굴 근거 + 구성 + B-roll + 체크리스트 + 회고 + 스크립트 링크 |

**이슈 description 형식:**

```markdown
## 발굴 근거

*(다른 후보로 갈아치울 때 참고용)*

### 데이터 신호
- 시의성: {수집한 헤드라인·매체·날짜}
- 타겟 도달성: {일반 매체 vs IT 전문지 vs 토론 사이트}
- 토론 신호: {HN, Reddit, news.hada.io 노출 여부}

### 우선순위: {선택값}
근거: {한 줄}

### 타겟 시청자: {선택값}
근거: {한 줄}

### 제목 후보
1. **{선택값}** — angle, 강·약점
2. {후보 2} — angle, 강·약점
3. {후보 3} — angle, 강·약점

### 썸네일 문구 후보
1. **{선택값}**
2. {후보 2}
3. {후보 3}

### 후킹 포인트
> {첫 15초 한 문장}

참고자료: {뉴스 URL들}

---

## 구성
- [ ] 도입 — 훅 + 오늘 다룰 내용 한 줄
- [ ] 본론 1 — {핵심 포인트 1}
- [ ] 본론 2 — {핵심 포인트 2}
- [ ] 본론 3 — {핵심 포인트 3}
- [ ] 마무리 + CTA

---

## B-roll / 자막 아이디어
- {시각 요소}

---

## 업로드 체크리스트
- [ ] 썸네일 완성
- [ ] 제목 A/B 후보 3개
- [ ] 설명란 + 해시태그
- [ ] 자막 + 인게이지먼트 포인트
- [ ] 출처/링크 정리

---

## 회고
*(영상 올린 뒤 작성)*
- 조회수·처음 48시간 반응:
- 댓글에 자주 보인 질문/요청:
- 다음에 살릴 포인트:

---

## 작업 단계

1. **편집** — 진우 (편집 완료 후 In Review로)
2. **검토** — 완수 (코멘트로 피드백, 통과 시 Done으로)
3. **업로드** — 플랫폼 게시

## 스크립트

[{에피소드 제목}]({document_url})
```

두 툴 모두 deferred — `ToolSearch`로 먼저 로드.

---

## 워크플로우

### 1단계 — 대상 결정

입력 유형에 따라 세 가지 모드 중 하나로 진행합니다.

**모드 A — 블로그 게시글 지정** (사용자가 글 제목이나 경로를 명시한 경우)
- 해당 글을 `markdown-blog/` 에서 찾아 읽습니다.
- 곧바로 2단계로 진행합니다.

**모드 B — 주제 문자열 지정** (사용자가 블로그와 무관한 주제·토픽·뉴스를 명시한 경우)
- 블로그를 읽지 않습니다.
- 사용자가 준 주제 문자열을 그대로 2단계 WebSearch 분석의 출발점으로 삼습니다.
- 곧바로 2단계로 진행합니다.

**모드 C — 블로그 후보 추천** (사용자가 "최근 글 중에 골라줘" 같이 소스를 지정하지 않은 경우)
- `markdown-blog/grid_Posts/` 와 `markdown-blog/grid_Papers/` 에서 최근 게시글 목록을 확인합니다.
- 다음 기준으로 3~5개를 골라 사용자에게 제시합니다:
  - **서사가 강한 것** — 사건/논란/극적 결과/놀라운 수치가 있는가
  - **비개발자도 이해 가능한가** — 기본 타겟이 "완전 비개발자"
  - **시의성** — 최신 사건/뉴스 기반은 초기 CTR이 높음
  - **시각화 여지** — 도해·차트·스크린샷·시연 거리가 있는가
- 각 후보에 대해 "왜 영상에 적합한지" 한 줄 이유를 함께 보여줍니다.
- `Dictionary/`, `CS229 Lectures/`, `Geoffrey Hinton/` 같은 시리즈/사전 폴더는 기본적으로 후보에서 제외합니다.
- 사용자가 후보를 선택하면 2단계로 진행합니다.

> **소스가 완전히 없으면** youtube-topic-finder 스킬을 사용하세요.

### 2단계 — 데이터 기반 분석

**제목 / 썸네일 문구 / 우선순위 / 타겟 시청자는 임의 판단으로 정하지 말고 외부 데이터에 근거합니다.**

`WebSearch` 툴 사용 (deferred → `ToolSearch`로 먼저 로드). 다음 쿼리들을 병렬로 실행:

1. **뉴스 헤드라인 수집** — `"{핵심 주제}" 뉴스` 또는 `"{topic} headline"` (한국어·영어 둘 다).
2. **시의성 신호** — 최근 보도가 며칠 단위로 나오는지. 주요 매체 노출 여부.
3. **타겟 도달성 신호** — 일반 매체 vs IT 전문지 분포.

#### 우선순위 결정 (높음 / 보통 / 낮음)

- **높음** — 최근 7일 내 주요 매체 다수 보도 + 일자리·돈·일상 직결
- **보통** — 1~3주 내 일부 보도 / evergreen 가치 있음 / 기본값
- **낮음** — 한 달+ 지난 이슈 / 특수 도메인

#### 타겟 시청자 결정

- **완전 비개발자** — 일반 매체 헤드라인 존재. 이 채널 기본값.
- **얕은 관심층** — IT 전문지 위주 보도.
- **개발자도 웃김** — 강한 근거 필요, 마지막 옵션.

#### 제목 후보 3개 (angle별)

- 호기심형: `"왜 X는 안 죽을까"`, `"X의 진짜 이유"`
- 단정·도발형: `"X는 사실 Y다"`, `"X가 졌다"`
- 사건·뉴스형: `"X에 무슨 일이 일어났나"`, `"X가 폭로됐다"`

#### 썸네일 문구 후보 3개 (2~4단어, 단정/도발)

#### 후킹 포인트 (첫 15초 한 문장)

청중이 익숙한 패턴/장면 + 그 안의 모순 구조.

**확인은 받지 마세요.** 분석 후 바로 3단계로.

### 3단계 — Linear Document + Issue 생성

**순서: Document 먼저 생성 → URL 받은 후 Issue 생성.**

#### 3-1. Document 생성 (`mcp__linear__save_document`)

title = 에피소드 제목, project = `Podcast 2026`

**Document content = 스크립트 전문만 (발굴 근거·구성·체크리스트는 이슈에):**

```markdown
## 스크립트 전문

청중: 완전 비개발자. 분량: 25~30분 longform.

**진행자** = 질문·반응·정리만 담당. 설명하지 않음. 1~2문장으로 끼어들기.
**진우** = 정보 설명 담당. 핵심 사실·수치·인물·메커니즘을 풀어 설명.
절대 역할 바꾸지 않음 — 진행자가 설명하거나 진우가 질문하면 안 됨.

### 도입 (2~3분)

**진행자:** {훅 제시 + 오늘 주제 한 줄}

**진우:** {충격 한 방 — 핵심 수치나 사건}

**진행자:** {반응 + 청취자 흥미 유도}

…

### 본론 1 — {부제} (7~10분)

**진행자:** {질문}

**진우:** {설명, 구체적 인물·날짜·수치}

**진행자:** {츳코미 또는 추가 질문}

**진우:** {심화 설명}

…

### 본론 2 — {부제} (7~10분)

…

### 본론 3 — {부제} (5~8분)

…

### 마무리 + CTA (2~3분)

…
```

#### 3-2. Issue 생성 (`mcp__linear__save_issue`)

Document 생성 후 받은 URL을 description에 삽입.

```markdown
## 작업 단계

1. **편집** — 진우 (편집 완료 후 In Review로)
2. **검토** — 완수 (코멘트로 피드백, 통과 시 Done으로)
3. **업로드** — 플랫폼 게시

## 스크립트

[{에피소드 제목}]({document_url})
```

## 스크립트 작성 규칙

**이 채널은 30분 내외 longform 팟캐스트.** 25~30분 = 5,000~6,000 단어 (한국어 200wpm).

**2인 대화체:**
- `**진행자:**` — 질문·츳코미·정리. 1~2문장 안에 끼어들어야 톤이 살아남.
- `**진우:**` — 설명 담당. 핵심 정보·수치·인물 풀이.
- 화자 사이 빈 줄 한 칸씩. 한 사람이 길게 독주하지 않도록.

**톤:** 존댓말, 잡담·예능 톤. 딱딱한 발표체 X.

**비개발자 원칙:**
- 개발 전문 용어 그대로 쓰지 않음. 어쩔 수 없으면 즉시 풀이.
- 고유명사 첫 등장 때 진행자가 "그게 뭐예요?"로 받아 풀이 유도.
- 숫자는 단위·규모감과 함께.
- 개발자 내부자 농담 금지.

## 카피 가이드

**제목:** 의문문 또는 단정형, 20자 내외.
**후킹:** 익숙한 패턴 + 그 안의 모순. 감정 있는 한 문장.
**썸네일:** 2~4단어, 단정·도발. 한국어 우선.

## 하면 안 되는 것

- 데이터 분석 건너뛰기.
- Document 없이 Issue만 만들기 (반드시 둘 다).
- Issue 없이 Document만 만들기 (반드시 둘 다).
- Document 먼저 만들고 URL 받은 뒤 Issue 만드는 순서 어기기.
- 본문에 이모지 사용.
- 썸네일 5단어 이상.
- 클릭베이트 과장 표현 (`충격`, `소름`, `미쳤다`).
- 영문 그대로 썸네일에 넣기.
- 스크립트 분량 줄이기 — 30분 longform.
- 중간 확인 받기 — 결과만 보고.
